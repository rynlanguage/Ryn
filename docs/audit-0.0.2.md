# Ryn 0.0.2 feature audit

Audited against the requested language, runtime, compiler, and toolchain checklist on 2026-10-06. The repository is an active, dirty working tree; this audit records capabilities found in source and documentation, not release readiness.

## Checklist status (2026-10-06, second pass)

Status of the requested checklist after verifying source, examples, and tests. Items marked `gap` are concrete, actionable work items.

- Syntax and basics: complete. `fun`, `:=`, `mut`, typed declarations, `when`/`else`, `choose`, `for`/`while`, `break`/`continue`, `return`, `use`, namespaces with `::`, `echo`, comments, and the full arithmetic/logic/bitwise operator set are implemented and tested.
- Types: complete except the partial items below. All integer widths, `f32`/`f64`, `bool`, `char`, `str`, owning `String`, arrays `[T; N]`, slices, tuples (non-empty), structs, enums, and type aliases (including generic aliases) work.
- Collections: `Vec<T>` and `Map<K,V>`/`HashMap<K,V>` are complete. Map iteration works through `keys() -> Vec<K>` and `values() -> Vec<V>` (cloned, consumed by the standard Vec loop); `values()` is rejected for move-only value types. A limited `Set<T>` exists through `Map<T, bool>`; a dedicated spelling remains optional future work.
- Error handling: complete. `Option<T>`, `Result<T,E>`, postfix `?` propagation, `panic`, `assert`, `assert_message`.
- Memory: stack values, heap-backed `String`/`Vec`/`Map`, `&T`/`&mut T` (scalar pointees), raw pointers `*T` with `&raw mut`, dereference reads/writes, restricted RAII with `#[drop(function)]`, move semantics, Ryn Guard, no GC, `sizeof`/`alignof`. Partial by design: general heap allocation APIs, pointer arithmetic, non-scalar pointees, and complete borrow lifetimes remain deliberate future work.
- Strings: complete. Unicode indexing/iteration, byte and scalar slicing, append, concat, `starts_with`, `ends_with`, `contains`, `find` (`Option<u64>`), `split`, `trim`, `String(number)` formatting, `to_*` and `try_to_*` parsing. The append-based builder is `String` itself (`push`/`append`).
- Generics: functions (inferred + turbofish), structs, enums, and aliases monomorphize. `first<T>(items: &[T]) -> &T` works for scalar element types. Missing: constraint bounds, full expression inference, generic enum payloads wrapping generic structs, reference returns for non-scalar elements.
- Modules: `use`, separate files, `mod.ryn`, file-scoped namespaces, `pub`/private symbols, path and Git dependencies, defined cycle behavior. Missing: field-level visibility, selective imports, registry fetching.
- Filesystem: complete. `read_file`/`try_read_file`/`read_file_result`, `write_file`, `create_dir`, `delete_file`, `delete_dir`, `delete_dir_all`, `read_dir`, `file_exists`, `is_file`, `is_directory`, and the path helpers.
- Process/system: complete. `arg`/`arg_count`, environment built-ins, `exit`, `run_process`/`run_process_args`, stdout/stderr/stdin.
- FFI: `extern "C"` imports (scalars, pointers, packed `repr(C)` records up to 8 bytes), `#[repr(C)]`, typed function pointers called through loaded symbols, and dynamic library loading (`load_library`/`load_symbol`/`unload_library`). Ryn functions now coerce to matching typed function pointers (`handler as HandlerFn` or an annotated binding) and native code can call them back: the [function pointer example](../examples/function_pointers.ryn) receives a Win32 `EnumWindows` callback that mutates a Ryn local through a raw pointer. Records larger than 8 bytes (Win32 `MSG`, `WNDCLASSEXW`, `RECT`) remain unsupported.
- Compiler-specific: the Rust bootstrap has tokens, AST, spans, UTF-8 source handling, diagnostics, collections, hashing, number parsing. The self-hosted prototype (`examples/self_hosted/`) has a lexer with interning, a source manager, an index-based AST arena, a Pratt parser, and a first fail-closed type pass.
- Toolchain: `ryn new`/`check`/`build`/`run`/`clean`/`lock`, `ryn.yaml`, path/Git dependencies, fingerprinted `build/cache`, debug/release profiles, rustc linker integration. Missing: incremental per-module compilation, linker library configuration, test/doc/fmt commands, target selection.

Priority order for the remaining gaps: records larger than 8 bytes, then linker library configuration. Closed on 2026-10-06: Map iteration (`keys()`/`values()`), function-to-function-pointer coercion with native callbacks, and direct enum formatting.

## Object model (0.0.3 start)

The `extend` block attaches methods to named structs: `self` borrows the receiver immutably, `mut self` mutably, so Ryn Guard rejects `mut`-method calls on immutable bindings and mutations propagate to the caller's local through the receiver's stack home. Methods support expression bodies (`fun health(self) -> i32 => self.health`), associated functions run through the type name (`Player::new(...)`), associated constants lower to zero-argument functions (`Player::MAX_HEALTH`), and method chaining on expression receivers is not supported yet (receivers must be locals). Struct fields are module-private without `pub`, closing the 0.0.2 field-visibility gap; cross-module private reads report R0426 and private methods R0425. Struct references (`&Player`/`&mut Player`) exist as the method-receiver representation: reads of owned fields clone, writes through `mut self` release the previous owner, and the borrow conflict rules reuse the existing reference machinery. `shape` declarations parse with a clear not-supported-yet diagnostic; structural conformance, generic constraints, `#[derive]`, operator contracts, and conditional extensions remain future work.

### Custom destructor implementation update

- `#[drop(release)]` now binds a private, non-generic `fun release(value: Resource)` to a non-generic, non-`repr(C)` struct. The first field must be a raw pointer; all fields must be scalar or raw-pointer values. Ryn Guard tracks the struct as one move-only owner, rejects direct calls to its destructor, and codegen runs it only while the handle is live. Custom-drop values can be transferred in fixed arrays. Direct `Vec<Resource>` and Vec elements whose ordinary struct fields contain Resource support drop glue, `push`, `set`, `take`, `clear`, and consuming iteration; clone, indexed/extracted reads and slices are rejected. `Map<K, Resource>` and `Map<K, Bundle>` values now support move-insertion, replacement, `remove`, `clear`, moves, parameters, returns and scope cleanup; Bundle may nest Resource through ordinary structs. Maps with these move-only values reject `get` and clone. A regular owning struct may hold such a Map field and drops it automatically. Plain scalar-only struct Map values support insertion, replacement, removal, cleanup, and `.get() -> Option<Struct>` with multi-slot payloads; choose-pattern binding and `?` propagation preserve all fields. Native `examples/map_struct_values.ryn` outputs `9`, `-1`, `30`, `true`, `0`. Structs with supported owned fields such as String now work as Map values for insertion, replacement, Map cloning, removal, cleanup, and `.get() -> Option<Struct>` through generated clone/drop plans. Enum payload plans recursively track owners inside structs and arrays, while choose binding and `?` clear transferred owner words before enum cleanup. `examples/map_owned_struct_values.ryn` natively retrieves a String-owning Label through both choose and `?`, clones the map, replaces one copy, removes from each, and observes both lengths reach zero. `Map.clone()` is rejected for move-only custom-destructor values; negative CLI probes verify this rejection with R0234. Nested custom-drop resources in enum payloads remain unsupported; move-only Map values may wrap them through ordinary structs, and whole fixed arrays containing wrappers can be transferred and cleaned as a unit. Negative CLI probes confirm `Vec<Bundle>.clone()` and `Vec<Bundle>.as_slice()` are rejected with R0234.

## Implemented foundations

- Core syntax: `fun`, inferred and typed declarations, `mut`, `when`/`else`, loops, loop control, returns, `echo`, comments, arithmetic/logic/bitwise operators, casts, and source diagnostics.
- Primitive types: signed and unsigned integer widths, `f32`/`f64`, `bool`, `char`, borrowed `str`, owning UTF-8 `String`.
- Type aliases for primitive, structure, enum, vector, and array types, including generic aliases such as `type OutcomeAlias<T> = Outcome<T>`. Alias parameters are substituted at use sites; declarations remain source ordered and aliases preserve the target's nominal identity. `examples/generic_enums.ryn` exercises a generic enum alias natively.
- Structures by value; enum variants and exhaustive `choose`, with scalar, `String`, `Vec`, `Map`, and nested enum payload cleanup. The runtime drop plan releases owning payloads, including maps nested inside `Option`/`Result`; [map_in_option.ryn](/C:/Users/ratko/Documents/RynLang/Ryn/examples/map_in_option.ryn) builds and runs this path. The Ryn Guard pass checks supported moves/borrows and emits deterministic cleanup for these owners and fixed arrays containing them.
- `Vec<T>` supports scalar and `String` elements plus owning `Map<K,V>` elements; clone callbacks deep-clone maps and drop callbacks release them. It now also supports `Vec<Struct>` when every structure field has a copyable or supported owning type; examples cover nested records, arrays, maps, enums, deep cloning, replacement, extraction, and consuming iteration. Unsupported borrowed-slice fields remain rejected. The vector has ownership checks, indexed access/extraction/mutation methods, deterministic cleanup, and consuming `for element in vec` iteration. Move-only Vec elements may contain custom-drop resources through ordinary nested struct fields; insertion/replacement/take/clear and consuming iteration invoke nested destructors, while cloning, indexed reads, extraction, and slices are rejected. `examples/custom_drop_nested_struct.ryn` covers nested struct transfer plus Vec cleanup and iteration. `Map<K,V>`/`HashMap<K,V>` use hashed buckets and implement `insert`, `get`, `contains_key`, `remove`, `len`, and `clear`; keys are integer, bool, char, or `String`, and values are scalar, `String`, `Vec<T>`, another `Map<K,V>`, regular structs with supported clone/drop glue, or a move-only ordinary struct wrapping custom-drop resources. Custom-drop Map values are cleaned on replacement, removal, clear, and drop, but cannot be read with `get` or cloned. Regular struct values with supported copyable or owned fields support storage, deep cloning, cleanup, and `get() -> Option<Struct>`; aggregate enum drop plans recursively track nested owners, and choose/`?` transfer ownership safely. Nested custom-drop values in enum payloads remain unsupported; move-only Map values and whole fixed arrays can contain resource wrappers through ordinary structs. Other owning keys/values move into the map and are released deterministically; `get` returns `Option<V>` and deep-clones supported owned values on `Some`, while missing keys return `None`. Maps are supported in structures and enum payloads, including `Option<Map<...>>`, when their payloads satisfy these restrictions. A limited `Set<T>` uses a `Map<T,bool>` representation and provides `add`/`insert`, `contains`, `remove`, `len`, and `clear` for supported key types; it is not a distinct runtime type. The native examples exercise nested maps, Map cloning through `Vec<Map<...>>`, custom-drop Map cleanup, structure fields, missing-key handling, `?` propagation, enum cleanup, and Set operations.
- Native code generation and runtime shims; project scaffolding and `ryn check`, `build`, `run`, `clean`; manifest parsing and optimization profiles.
- Fixed arrays are stack/local values. They support primitive, borrowed `str`, owning `String`/`Vec<T>`/`Map<K,V>`/enum, nested arrays, and recursively nested structures/arrays whose leaves are scalars, `str`, `String`, `Vec<T>`, `Map<K,V>`, or enums. `examples/struct_arrays.ryn` verifies nested structure and array layout, owner cloning, indexing, field reads, indexed replacement, and by-value array returns; `examples/enum_arrays.ryn` verifies enum-array cloning for `String`, `Vec`, and `Map` payloads. Enum clones copy the payload and deep-clone its active owned fields according to the runtime drop plan. Dynamic `String` and `Vec<T>` use heap storage; there is no garbage collector. Custom destructors exist for restricted scalar and raw-pointer resource-handle structs. Resource handles can be nested in ordinary structs and move-only Vec elements, then transferred, returned, or consumed by iteration; custom drop glue inside enum payloads remains unsupported; move-only Map values may wrap resource-owning structs and are cleaned by generated callbacks. Fixed arrays may contain such resources through ordinary structs when the array is moved as a whole.
- Positional tuples `(T0, T1, ...)` are represented as compiler-generated structures and support inferred/annotated construction, function parameters and returns, numeric field access (`.0`, `.1`, ...), and mutable field assignment. `examples/tuples.ryn` verifies inference, signatures, aggregate returns, and field reads/writes. Empty `()` values and tuple-driven generic type inference remain unsupported; tuple elements otherwise use regular structure ownership and layout rules.
- String support includes UTF-8 scalar-aware character count/index and iteration for owning `String` and borrowed `str`; `String.slice` copies a byte range at valid UTF-8 boundaries, while `String.slice_chars(start,end)` copies by Unicode scalar indices. `examples/unicode_slices.ryn` checks multibyte characters, combining marks, empty ranges, and compatibility with byte slicing. Append/concat, trim, prefix/suffix/contains, and deterministic ownership are available.
- Tests and examples already exist for the bootstrap compiler, native execution, diagnostics, enums, vectors, and owning cleanup. They are evidence for those specific areas only.

## Missing or partial against the request

- Fixed arrays `[T; N]`, literals, by-value parameters/returns, bounds-checked reads, and mutable indexed assignment work for scalar values, `str`, `String`, `Vec<T>`, `Map<K,V>`, enums, nested arrays, and recursively nested structures/arrays whose leaves are copyable scalars, `str`, `String`, `Vec<T>`, `Map<K,V>`, or enums. Owning reads deep-clone active enum payloads and other owners; writes drop replaced owners. Native examples verified nested reads, String-array transfer/return, Vec<String> cloning, nested struct/array layout and String/Map owner cloning, enum-array cloning of String/Vec/Map payloads, struct array indexing/field reads/return, indexed replacement, and negative-index diagnostics. Arrays and context-typed array literals (including empty literals) can be passed to `&[T]` parameters when elements have generated clone/drop support; `examples/array_slices.ryn` verifies primitive arrays/literals and String elements. The backend materializes flattened array values into a call-scoped stack buffer, and slice element reads clone owning values before they enter the callee. Slice descriptors cannot escape through a return or local binding; functions may return a tracked reference to a scalar element. Generic slice functions also infer their element type from arrays; `examples/generic_functions.ryn` exercises this path. This is not yet a zero-copy borrow of array storage. Set-valued array elements work through the Map representation; `examples/set_arrays.ryn` verifies array construction, independent element mutation, replacement, `contains`, `len`, and `remove`. Tuples support positional construction, annotations, function signatures/returns, and numeric field access; they use the structure ownership/layout path. Empty tuple values and generic type inference from tuple expressions remain unsupported. Immutable Vec slices support elements with generated clone/drop support, including `String`, `Map<K,V>`, and nested structures such as `Vec<Struct>`, as `&[T]` function parameters, `as_slice()`/`slice(start,end)`, bounds-checked indexing, `len()`, and non-consuming iteration; owning element reads clone into the callee. Slice descriptors cannot be returned or stored in locals/structure fields; general reference lifetimes, mutable slices, and slices of types without generated clone/drop support remain absent.
- `sizeof(Type)` and `alignof(Type)` are compile-time `u64` expressions. They use the current logical 64-bit target layout, including natural primitive sizes, pointer-backed owner handles, pointer/length pairs, array strides, and padded structure fields; `examples/layout.ryn` checks representative scalar, array, structure, `str`, and String layouts. `#[repr(C)]` is parsed and marks structs for C interoperability. `extern "C"` accepts repr(C) integer, bool, and char records as covered by `examples/ffi_repr_c.ryn`, plus packed records of up to 8 bytes containing `f32`/`f64` fields; `examples/ffi_float_records.ryn` checks those declarations but is not yet linked to a runtime C symbol. Aggregate float lowering uses an integer register representation for the currently supported Windows x86_64 ABI. Other platform ABIs and records larger than 8 bytes remain unsupported.
- Generic functions support inferred or explicit call-site type arguments and monomorphization, including public generic functions reached through module aliases. Generic struct templates specialize on concrete type arguments, including direct type-parameter fields, collection fields such as `Vec<T>`, and nested user-generic fields when the inner template is declared first; `examples/generic_structs.ryn` verifies scalar and owned-String records, nested `Nested<i32> -> Box<i32>`, function transfer, mutation, and cleanup. Generic enum templates specialize concrete direct payload types and support constructors, nested generic enum payloads, multiple type parameters, and exhaustive `choose`; `examples/generic_enums.ryn` verifies inferred construction from `Outcome<i32>` context, explicit `Outcome::<String>` patterns with owned payloads, unit variants, `Outer<String> -> Inner<String>`, and `Selection<String, i32>`. `examples/generic_functions.ryn` verifies `identity<T>(T)->T`, `first<T>(&[T])->&T` and `first_value<T>(&[T])->T` from Vec slices and fixed arrays, and `take<T>(Vec<T>)->Vec<T>` for `i32`; `examples/generic_explicit.ryn` verifies turbofish calls where `T` appears only in the return type and an explicitly typed void call; `examples/namespaced_module_project` checks and runs an imported namespaced generic call with an explicit type argument. Generic aliases such as `OutcomeAlias<T> = Outcome<T>` are source-order declarations, substitute their arguments at use sites, and can be imported through project module aliases; `examples/generic_enums.ryn` exercises local use and `examples/module_project` exercises an imported `TokenList<T>` alias. Function specializations are capped at 256. Recursively declared generic fields, generic enum payloads wrapping a generic struct, trait/constraint bounds, type inference for every expression form, and general reference lifetimes remain unsupported. The borrowed `first` implementation currently supports scalar element types.
- `Option<T>` and `Result<T,E>` specialize concrete payload types found in type annotations/signatures. Their variants construct and match through expected types (`Option::Some/None`, `Result::Ok/Err`) and use enum ownership/drop; nested combinations such as `Option<Result<i32, String>>` work. The postfix `?` consumes either wrapper: it returns the success payload, or propagates `Err(E)` through a matching `Result<U,E>` function / `None` through an `Option<U>` function, cleaning live local owners on the early-return path. `examples/option_result.ryn` covers success, failure, and nested enums. These are compiler-specialized forms: constructors need an expected type, and generic types/constraints remain absent.
- `String(number)` formats all integer and float widths. The existing `to_i*`/`to_u*`/`to_f*` methods still terminate with a diagnostic for invalid or out-of-range values; the new `try_to_*` methods return `Option<T>` for all ten numeric types, verified by `examples/string_parse_options.ryn` for boundary values, malformed input, and range failure. `read_file` likewise terminates on I/O or UTF-8 errors. `exit(i32)` terminates with a caller-selected process status after releasing live compiler-known owners; it runs generated cleanup, including supported custom destructors. `panic`, `assert`, and `assert_message` write the failure to stderr, release live compiler-known owners, and terminate with status 1. This runs generated cleanup and supported custom destructors without Ryn stack unwinding.
- `String.find` returns `Option<u64>` containing the zero-based Unicode scalar index; no match returns `Option::None`. The compiler lowers the runtime's sentinel internally into an owning Option enum, so the user-facing API has no sentinel. `String.split` accepts `str` or `String` and returns an owning `Vec<String>` with UTF-8 separator semantics. `ryn run examples/dynamic_strings.ryn` verifies hit/miss results, splitting runtime-generated text, extraction/printing, and indexed/direct Unicode-scalar iteration over both owned and borrowed strings.
- File-scoped `namespace path::nested;` declarations qualify functions, structs, enums, and aliases; `namespace;` resets to the root namespace. Qualified paths use `::`, and unqualified function calls, struct types/literals, enum types/constructors/patterns, and local aliases resolve within the current namespace. The native [namespace example](/C:/Users/ratko/Documents/RynLang/Ryn/examples/namespaces.ryn) covers unqualified struct field/signature types, enum construction and matching, local function resolution, and qualified calls from root. [A multi-file namespaced project](/C:/Users/ratko/Documents/RynLang/Ryn/examples/namespaced_module_project/ryn.yaml) also passes `ryn check` and `ryn run`, including an unqualified call between private functions in the namespaced module. Block-scoped namespaces remain unsupported; public type aliases can be imported through module aliases, as the multi-file `examples/module_project` demonstrates.
- Project modules load from `src/` using `use path::module`; resolution accepts `path.ryn` and `path/mod.ryn`, rejects source-root escapes and ambiguous duplicate imports, deduplicates files, and handles import cycles by loading the graph once before resolving signatures. `pub fun` calls resolve through the module alias (for example, `use compiler::lexer` exposes `lexer::token_name`), private functions remain callable inside their own module, and private cross-module calls are rejected. Public structs, enums, and type aliases can be named through the imported alias in annotations, qualified struct literals, constructors, and `choose` patterns. - Local scalar references (`&T`, `&mut T`) and raw pointers (`*T`, `&raw mut value`) support native pointer representation, function parameters, dereference reads, and writes through mutable/raw pointers; `examples/references.ryn` checks shared/mutable reference calls, direct local reads after pointer writes, and raw pointer calls. Immutable bindings cannot be mutably borrowed, and writes through shared references are rejected. The implementation currently supports scalar pointees only, requires local-variable address operands, and does not track full borrow lifetimes or provenance through arbitrary calls. It prevents references to stack locals and by-value parameters from escaping, tracks direct reference parameters and scalar element references returned from borrowed slices, rejects known conflicting aliases in a call, and blocks direct writes or source-collection mutation while a scalar element is borrowed. Unknown reference provenance cannot be stored; lifetimes remain lexical, and raw pointer dereference is unchecked. References are not yet memory-safe as a general system. Restricted custom resource-handle destructors are implemented; nested ordinary structs and move-only Vec elements can own them. Whole fixed arrays of nested resource wrappers now move and clean up; element-level moves and nested Map/enum payload support remain absent. `sizeof` and `alignof` are implemented as compile-time `u64` layout queries, with primitive, array, String, `str`, and structure layouts covered in `examples/layout.ryn`. Ryn Guard tracks compiler-known owners, restricted custom-drop roots, and nested owners in ordinary structs/move-only Vec values; complete reference lifetimes, element-level custom-drop array moves, and nested custom drop glue inside enum payloads remains absent; move-only Map values now use generated drop callbacks. Panic and failed assertions run generated cleanup, including restricted custom destructors, before terminating without Ryn stack unwinding. `examples/panic_cleanup.ryn` and `examples/assert_cleanup.ryn` each keep a String owner live; both pass `ryn check`, print the expected diagnostic, and exit 1 when natively run. `assert(true)` was verified to continue execution.
- Filesystem built-ins provide UTF-8 `read_file` and `try_read_file`, `write_file`, recursive `create_dir`, `delete_file`, empty-directory `delete_dir`, recursive `delete_dir_all`, `file_exists`, `is_file`, `is_directory`, sorted full-path `read_dir -> Vec<String>`, `path_join -> String`, `path_parent`, `path_file_name`, `path_extension`, and `path_is_absolute`, based on host path semantics. Filesystem calls borrow owned `String` arguments as UTF-8 path/data views, including temporary `path_join` results. `examples/filesystem_paths.ryn` checks path components and absolute-path detection, writes and deletes joined paths, and iterates the sorted directory entries. Mutations return `bool`; `try_read_file(path) -> Option<String>` returns `None` for I/O or invalid UTF-8. `read_file_result(path) -> Result<String, i32>` returns the contents or an error code: 1 not found, 2 permission denied, 3 invalid UTF-8, 4 invalid path input, and 5 other I/O errors; `examples/read_file_result.ryn` exercises success and a missing-file result. `read_file` and `read_dir` still terminate with a runtime diagnostic on failure. Environment access provides `env_exists`, `env_or`, `set_env`, and `remove_env`; stdout/stderr writers and whole-stdin UTF-8 reading are also present. `run_process` and `run_process_args(program, Vec<String>)` return a numeric exit code or `-1` when launch fails or no numeric status is available. The process example verified argument delivery and code `7`; the stdin example accepts UTF-8 input through EOF. `extern "C"` imports link external scalar symbols for integer, float, bool, and char values. `#[repr(C)]` records with one integer, bool, or char field, and multi-field integer/bool/char records whose C layout is exactly 2, 4, or 8 bytes can be passed to and returned from C functions. `examples/ffi_repr_c.ryn` exercises packed 2-byte, 4-byte (including internal padding), and 8-byte aggregate argument/return paths. The native backend packs fields into an integer ABI value and this lowering has been verified on Windows x86_64. Ryn-side declarations can use qualified namespaces while retaining the unqualified C linker symbol; `examples/ffi_scalar.ryn` calls `c::abs` and prints `42`. A public external declaration in the namespaced `compiler::lexer::ids` module is also imported and called as `lexer::ids::abs` in `examples/module_project`, which prints `17`. Small float-field records up to 8 bytes are supported for direct C calls and `extern "C"` function-pointer signatures on Windows x86_64. `examples/ffi_float_records.ryn` runtime-checks the direct calls and compiles indirect-call bodies; the indirect aggregate path is not separately executed. Larger C records and non-C function pointers with aggregate values remain unsupported. Runtime library loading, symbol lookup, unloading, and null checks are implemented for Windows and Unix; `examples/dynamic_library.ryn` loads `ucrtbase.dll`, casts the `abs` symbol to `AbsFn`, passes it through a typed Ryn function parameter, invokes it indirectly, checks a missing symbol, and unloads the library. The example is platform-specific and its end-to-end native test is Windows-only. Calling through a symbol is an unsafe boundary: callers must ensure the pointer names a live function with exactly that ABI/signature and keep its library loaded until after the call. Larger aggregate arguments/results, non-C ABI function pointers with aggregates, and general safety checking remain unsupported. Scalar raw pointers and address/dereference operations have the experimental restrictions summarized above. `stdlib/path` provides a separate owning `Path` structure and public constructors/operations, verified as an imported local dependency by `examples/path_project` (including String I/O and cleanup). Operations consume Path values because general references to owned structures are not implemented yet; callers reconstruct a path when they need multiple independent operations. `echo`, process arguments and `i32` main exit status are present.
- Project `build`/`run` now use a persistent artifact fingerprint under `build/cache`: it hashes the compiler executable, optimization profile, manifest, optional `ryn.lock`, all Ryn source files in local path dependencies, and output identity, and verifies the generated executable before reuse. Unchanged projects report `up-to-date`; changed inputs or modified/missing outputs rebuild. `ryn.yaml` accepts profile-specific `build.debug` and `build.release` optimization settings (`speed`, `size`, `none`), overriding the legacy shared `build.optimize`; standalone builds default to no optimization in debug and speed optimization in release. `examples/profile_project` was built and run in both profiles; the debug and release native executable hashes differ, and each profile has a separate cache fingerprint. `ryn lock <project>` writes a deterministic `ryn.lock` graph for local path and Git dependencies, including transitive package names, versions, parent edges, declared sources, and pinned Git commits; project `check/build/run` reject a present lockfile that differs from the current dependency graph and explain how to refresh it. `examples/dependency_project/ryn.lock` records its `mathlib -> coremath` path graph. - A first executable Ryn lexer prototype now lives in `examples/self_hosted/lexer.ryn`. It scans Unicode scalar values, tracks UTF-8 byte and scalar spans, skips whitespace, `//` comments, and nested `/* */` comments, recognizes the complete current Rust keyword set, ASCII identifiers, decimal/binary/hex integer literals, decimal `_` separators, decimal fractions and exponents, quoted strings with basic escapes, single-character punctuation, character literals, and all two-/three-character operators used by the current Rust lexer. It returns a `Lexed` structure containing `Vec<TokenSpan>`, `Vec<LexError>`, and decoded string values referenced by token payload index; token records carry numeric kind codes, integer/f64/char payloads, and source spans so raw lexemes can also be read by byte range. It decodes simple escapes and `\\u{...}` Unicode scalar escapes in strings and characters. `lex_file(path)` uses `try_read_file`; an unreadable or invalid UTF-8 source produces a `Lexed` result with error code 11. Error records cover unknown characters, unterminated strings/block comments, invalid character-literal length/escape, invalid Unicode scalar escapes, unsupported string escapes (code 10), invalid radix digits/missing radix digits, invalid separators, and missing exponent digits. `format_lex_error` maps error codes to messages and renders the source line, line/column, and span underline; it counts Unicode scalar columns and handles LF, CRLF, and CR line endings. Integer overflow validation covers decimal, binary, and hexadecimal literals through `u64::MAX`; positive f64 exponent overflow is reported as code 13, including very large exponent text without overflowing the exponent accumulator. The self-hosted assertions cover the largest finite f64 spelling and overflowing decimal/exponent cases. This is range checking, not a correctly rounded decimal-to-binary conversion guarantee. Unicode escape validation rejects leading underscores while preserving Rust-accepted internal/repeated/trailing underscores; scalar escapes, common escapes, invalid forms, and decoded results are covered by self-hosted assertions. Full Rust escape parity, detailed file I/O errors, and integration with the shared source manager remain. The example passes `ryn check` and native `ryn run`, covering Unicode escape decoding, invalid scalar rejection, disk lexing, the missing-file error result, and formatted diagnostics after a multibyte Unicode character. A heap-corruption bug in function calls returning multi-slot structures was fixed: callers now reserve the complete aggregate return width instead of one scalar slot. The lexer’s disk reads now run after its other local allocations; repeated native runs and 4–48-live-String reproductions exit successfully.
- The bootstrap compiler has a Rust lexer, recursive AST/parser, UTF-8 source spans, source-file loading and diagnostics; it has no general-purpose allocator, and the self-hosted interner is not yet wired into the actual compiler front end. `examples/self_hosted/source_manager.ryn` is an executable first port of file loading, LF/CRLF/CR line-start indexing, byte-offset lookup, Unicode-scalar columns, and line extraction. `examples/self_hosted/lexer.ryn` now combines its token stream with an index-based AST arena and a Pratt parser for literals, names, unary operators, arithmetic, comparison, bitwise/logical operators, precedence, grouping, and block-valued `when`/`else` expressions. Nested conditional expressions parse into arena nodes and execute in the recursive evaluator; malformed missing-`else` input receives a parser diagnostic. The lexer interns identifier spellings into a `Map<String, u64>` and stores symbol IDs in identifier token payloads; the repeated-name example produces one symbol ID for all occurrences. AST name nodes retain those IDs, and the evaluator resolves local variables by symbol ID. Its minimal program parser handles `fun name<T>(parameters) -> Type { ... }` declarations, records generic type parameter names in the AST, preserves composite parameter/return type source spans (including references and slices such as `&[T]`), and parses primitive-typed parameters, call-expression syntax and argument lists, `name := expression`, `mut name := expression`, simple `name: Type = expression` declarations, `=` and compound assignments, statement-level `when`/`else`, `while`, exclusive integer-range `for`, `break`, `continue`, `echo expression`, and `return expression`, and builds indexed AST nodes; it reports lexical, malformed-primary, missing-close, trailing-token, and unsupported-statement errors with byte spans. Lexical and arithmetic-parser errors can both be rendered with an error code, message, source excerpt, Unicode-scalar line/column and span underline. The example evaluates integer `+ - * / %`, comparisons, boolean `&&`/`||`, bitwise `&`/`|`/`^`/`~`, shifts, and logical `!`; it evaluates `7 + 9 * (2 + 1)` to `34` and `(8 >= 8) && ((6 & 3) == 2) && ((1 << 3) == 8)` to `1`. Its recursive AST evaluator executes inferred and explicitly annotated local declarations, `mut` declarations, identifier reads, `=` and compound reassignment, conditional expressions and statements, loops and loop control, `echo`, and early `return`; `limit := 7; mut value: i32 = 3; echo value + limit * 2; value += 1; value = value * 2; echo value; return value` produces `17`, `8`, and return value `8`. The prototype records simple type annotations and return types in the AST but does not resolve or type-check them. Non-generic function calls execute with positional scalar arguments and return values; recursive calls are covered by an in-example sum function (`sum(5) == 15`). Function overloading, argument/type validation, and propagation of function-local output remain unsupported. The parser still accepts only this minimal subset; generic struct/enum declarations, explicit generic call arguments, collection expressions, namespaces, and modules are not parsed; generic function signatures are syntactically represented but not resolved or monomorphized; function calls execute, but the prototype does not type-check declarations or arguments. A reusable public source-manager module now indexes in-memory UTF-8 text and files, locates byte offsets, and extracts lines. `examples/self_hosted_project` imports it into the lexer module; its diagnostic formatter uses the manager for line, Unicode-scalar column, and excerpt while retaining byte spans for underline width. ### Self-hosted parser update

- `examples/self_hosted/lexer.ryn` parses nested block-valued `when`/`else` expressions, nested array literals, postfix array indexing, field and method access, and integer/boolean, exclusive integer-range, and `_`-wildcard `choose` expressions into its index-based AST arena. Generic function declarations retain type-parameter names and composite parameter/return type spans in the AST; an in-example assertion covers `first<T>(items: &[T]) -> &T`. Its recursive evaluator now resolves names from the current environment, executes root and nested statement blocks, re-evaluates `while` conditions, iterates exclusive integer ranges, and propagates `break`, `continue`, and `return` through nested blocks and loops. In-example assertions exercise a while-loop sum (`6`), for-range sum (`9`), continue/break behavior, and nested statement-level `when`/`else` branches. It also selects integer/boolean choose arms, exclusive ranges, and wildcards. Enum constructors/patterns, inclusive ranges, or-patterns, exhaustiveness checking, generic type resolution/monomorphization and general collection semantics remain absent; generic function declaration syntax is now parsed into the AST; ordinary function declarations and call expressions parse into AST nodes, and the evaluator runs a `main` function, passes positional scalar arguments, returns scalar values, and supports recursive calls. Type resolution/checking and non-scalar call values remain incomplete.

The self-hosted expression prototype now has a fail-closed first type pass for integer, boolean, float, String, and char literals; unary `!`, `-`, `~`; numeric arithmetic; integer remainder/bitwise/shift; logical operators; comparisons; boolean `when` conditions with matching branch types; and integer/boolean `choose` scrutinees with matching literal patterns and arm result types (integer-only ranges). Identifier types can be supplied through a symbol/type environment. Program/block analysis builds that environment from inferred declarations, checks assignments against existing types, resolves primitive annotations, checks `echo`/`return` expressions, validates statement-level `when` and `while` conditions, and checks integer `for` ranges. Nested blocks receive copied environments, so branch/loop locals do not escape; `for` variables are available inside the loop body. It also checks non-generic function bodies with primitive parameter types, verifies explicit return types, and resolves direct calls against a pre-collected function table, checking arity and argument types (including recursive calls). `format_type_error` formats the first semantic failure as an `R0300` diagnostic at the failing AST span. Embedded assertions cover correct/incorrect variable uses, annotations, incompatible operators, scope escape, return mismatches, call mismatches and formatted diagnostic codes. Control-flow joins/state changes, loop-control placement, generic functions, aggregate types, pattern exhaustiveness, declaration mutability and rich semantic diagnostics remain absent. `ryn check examples/self_hosted/lexer.ryn` and native `ryn run` both passed after this change.

## Implementation order

1. Arrays of recursively nested structures and enum values with supported runtime clone/drop glue, positional tuples, and immutable Vec slices now pass through parser, semantic analysis, ownership tracking, and native codegen within the limits listed above; next extend slice borrowing and remaining aggregate combinations such as Set elements.
2. Generic functions now monomorphize inferred and explicit concrete calls; extend expression inference, generic types, constraints, and reference returns. The current specialized `Option`/`Result`/`?` path works. Legacy numeric String conversions still terminate on invalid input; `try_to_*` returns `Option<T>` for numeric parse failures. `try_read_file` provides `Option<String>` for I/O/UTF-8 success or failure but no detailed error payload.
3. File-scoped namespaces with qualified paths and local function/type/enum lookup are implemented; Git dependencies can be locked to commits and loaded from the per-project cache. Add block-scoped namespaces and registry version resolution.
4. Direct Unicode string iteration, String search/split, numeric conversions and the append-based builder now exist. Restricted Map/HashMap and Set APIs exist; extend their generic constraints and runtime layouts.
5. Extend ownership and Ryn Guard with complete borrow/lifetime rules and element-level custom-drop array moves and nested custom-drop enum payloads. Whole fixed arrays and move-only Map values can own nested resources through ordinary structs. Restricted custom destructors and all listed control-flow cleanup paths are implemented for scalar/pointer resource handles.
6. Filesystem/process/environment basics now exist; finish path/value ergonomics, reference-safe borrowing for owned values, and the remaining C ABI boundary (aggregate function-pointer arguments/results, broader record layouts, and dynamic call coverage beyond scalar signatures).
7. Build/cache/toolchain completion, then integrate `examples/self_hosted/source_manager.ryn` with `examples/self_hosted/lexer.ryn`; extend its arithmetic AST and minimal statement parser to the Ryn grammar, then continue with diagnostics, semantic analysis, backend, and CLI in bootstrap-safe stages.

This is a rolling audit. Keep the v0.0.2 goal open until each requested language, runtime, compiler and toolchain capability is implemented and verified; the missing items above remain part of that same objective.
