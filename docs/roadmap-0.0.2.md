# Ryn 0.0.2: language and systems foundations

Ryn 0.0.2 should make the compiler useful for larger programs while avoiding accidental commitments to ownership, memory layout, and a public ABI. Graphics functionality belongs in a separate future `Ryn-GFX` project; this repository remains the language and compiler.

## Dependency order

1. Owning UTF-8 `String`, Unicode scalar `char`, and the ownership/runtime foundation. The implementation now has dynamic String methods, numeric formatting/parsing, move checking and deterministic built-in cleanup; `String.find` returns `Option<u64>` with the UTF-8 scalar index. [memory-model.md](memory-model.md) specifies current behavior.
2. `Vec<T>`, enums and `choose`, arrays/slices and tuples are implemented within the audited limits. Immutable Vec slices support elements with generated clone/drop support, including `String`, `Map<K,V>`, and nested structures; fixed arrays of supported elements become call-scoped flattened slice buffers. Indexing and iteration clone owned elements into the callee. Mutable slices and slice escape through returns or locals remain absent. `Map<K,V>`/`HashMap<K,V>` provide hashed storage for scalar/String keys, scalar/String/Vec/Map values, Vec<Map> elements, move-only custom-drop values directly or through ordinary struct fields in Map values, and move-only Vec elements whose ordinary struct fields own custom-drop resources; `get` returns `Option<V>` only for cloneable values. A limited Set API currently uses `Map<T,bool>`. Struct Map values support storage/removal/cleanup and `get() -> Option<Struct>`, including structs with supported owned fields. Whole fixed arrays may contain resources through ordinary structs and are moved/cleaned as a whole. Nested custom-drop resources in enum payloads, arbitrary generic payloads, and a distinct Set representation remain unsupported. Scalar-local references and raw pointers now have an experimental implementation; complete lifetimes, alias checking, and reference-backed collection access remain.
3. User functions now support inferred generic parameters through call-site monomorphization (see `examples/generic_functions.ryn`). Explicit type arguments, generic structures/enums, and generic aliases now have basic monomorphized support; extend inference across more expressions and add constraints. `Option<T>`, `Result<T, E>` and error propagation work for concrete specializations; input and parsing APIs should use this result model. Type aliases support source-order generic aliases; compile-time constants remain to be added alongside type resolution.
4. Extend the current ownership and Ryn Guard foundation with complete reference/lifetime rules, element-level moves from custom-drop arrays, and nested custom-drop enum payloads. Whole fixed arrays containing resource wrappers and move-only Map/Vec values may already carry custom-drop resources through ordinary structs; preserve exactly-once moves and cleanup as layouts expand. Restricted resource-handle structs already support `#[drop(function)]` cleanup.
5. File-scoped `namespace path::nested;`, `namespace;`, qualified paths, module `use`, non-generic public imported type aliases, visibility, and local path dependencies are implemented. Generic imported aliases, block-scoped namespace declarations, and broader dependency resolution remain.
6. Restricted RAII and custom destructors are implemented for scalar/raw-pointer resource handles, including cleanup on scope exit, return, loop control, panic, assertion failure, and process exit. Extend supported layouts while preserving move semantics and exactly-once cleanup; nested resources in ordinary structs and move-only Vec elements are supported, while element-level array moves plus Map and enum-payload nesting need additional drop glue. Whole-array ownership already handles ordinary-struct nesting. Ryn does not unwind the stack.
7. Add the system boundary deliberately: logical `sizeof`/`alignof` queries now describe the current 64-bit Ryn type layout; scalar raw pointers and a narrow C ABI/`repr(C)` subset are implemented. A narrow runtime loader and `i32(i32)` function-pointer call are implemented; general typed function pointers, target configuration, atomics, threads, SIMD, broader aggregate ABIs, and safety/lifetime rules remain future work.
8. Expand the CLI and build workflow with formatting, tests, docs, benchmarks, profiles, target selection, and debugger information. Project builds now reuse a fingerprint-verified whole-project executable when every input is unchanged; per-module/stage incremental compilation remains future work.

This is a dependency guide, not a promise to implement every item in one release. Do not create the future repositories as placeholders. Split a component out only when it has an independent architecture and lifecycle.

## Current implementation checkpoint

The bootstrap now executes enum construction and exhaustive `choose` on the native backend. Unit variants and payload fields are supported for scalar types, `String`, `Vec<T>`, `Map<K,V>`, and nested enums; pattern bindings move owning payloads and runtime drop plans release fields left in the selected enum. `Option<T>` and `Result<T,E>` specialize concrete types from annotations/signatures, support nested combinations, and use the expected type for constructors. Postfix `?` propagates `Err(E)` through matching `Result` functions / `None` through `Option` functions and cleans local owners on early return. `examples/option_result.ryn` covers these paths natively. Generic functions with inferred type parameters monomorphize at call sites; `examples/generic_functions.ryn` covers identity, slice indexing, and Vec transfer. Basic generic structures/enums, explicit generic calls, and generic aliases are implemented; constraints and generalized inference remain incomplete. `first<T>(items: &[T]) -> &T` now returns a tracked reference to scalar elements from Vec slices or fixed arrays; Ryn Guard carries known source origins through direct reference-returning parameters and blocks moves/mutations for the lexical reference scope. General lifetime checking, non-lexical lifetimes, and references to owned collection elements remain incomplete. Fixed arrays, type aliases, file-scoped namespaces, project modules, filesystem basics, environment access, streams, process launch, panic, and assertions have bootstrap implementations and runnable examples. Immutable Vec slices of clone/drop-supported elements, including String, can be passed, indexed, measured, and iterated inside a call; fixed arrays materialize a call-scoped slice buffer for the same supported element types. `Vec<Struct>` now works for copyable scalar-only fields, which lets `examples/self_hosted/lexer.ryn` return a `Lexed` structure containing token records and lexical error records with UTF-8 byte/scalar spans. The prototype scans the full current keyword inventory, character literals, decimal/binary/hex integers, decimal fractions/exponents, and nested block comments; it interns identifiers and carries symbol IDs into AST name nodes and local-variable evaluation. It reports basic invalid-character, character length, separator, radix, unterminated-string/comment, and missing-exponent errors using numeric codes. Human-readable diagnostics and escape decoding are present; integer overflow is checked through `u64::MAX`, positive f64 exponent overflow is reported (including very large exponents), and Unicode escape separators are validated against Rust behavior; exact decimal-to-binary rounding and compiler integration remain. Owning or nested structure fields in Vec, array slices, tuples, general reference/lifetime checking and mutable slices remain incomplete; restricted `#[drop(...)]` resource-handle cleanup is implemented, while nested custom drop glue remains incomplete; the owning `Path` module now exists, but its consuming API awaits general references to owned values before it can offer borrowing methods. FFI remains partial.

## Canonical syntax

The old `fn`, `let`, `if`, and `print` spellings are removed rather than kept as aliases. Canonical examples use `fun` for functions, `name := value` for inferred declarations, `mut name := value` for mutable inferred declarations, `when` for conditions, and `echo value` for output. An explicit type uses `name: Type = value`, with `mut` before the name when mutation is allowed. The declaration rule is: `:=` introduces a new inferred binding; `:` introduces an explicit type, followed by `=` and its initializer.

`choose` is the pattern-matching keyword. File-scoped `namespace math::integer;` qualifies declared functions and types; `namespace;` returns to the root. Fully qualified paths use `::`, and unqualified functions, struct types/literals, and enum types/constructors/patterns resolve inside the current namespace. Block-scoped namespaces remain incomplete. Project `use path::module` imports load `.ryn` or `mod.ryn` files under `src/`; public functions, structs, and enums are addressable through an imported alias, module-private helper calls work locally, and private cross-module function calls are rejected. Direct and transitive local `path` dependencies in `ryn.yaml` are loaded and linked. Cycles load each canonical file once before signatures are resolved. Imported type aliases, including generic aliases, are supported; field-level visibility and registry fetching remain incomplete. See [audit-0.0.2.md](audit-0.0.2.md) for verified scope.

## Fixed arrays: initial design

Implementation status: the bootstrap parser, semantic analysis, ownership pass, and native backend support fixed arrays of scalar values, `str`, `String`, `Vec<T>`, and nested arrays. Arrays pass and return by value, reads and writes are bounds checked, writes require a mutable named local, reads clone owning elements, and writes destroy replaced owners. Structure/enum elements and slices remain incomplete.

- The type syntax is `[T; N]`; `N` is a compile-time integer literal and part of the type. The initial implementation accepts zero-length arrays as well as non-empty arrays.
- Array values use `[value, ...]` literals. Every element is evaluated once from left to right. A contextual type determines the element type and required length; otherwise a non-empty literal infers both from its elements. An empty literal requires an expected array type.
- Arrays are fixed-size values. Assignments, parameters, returns, and structure fields preserve value semantics. Array-to-slice views remain unsupported and will need stable storage plus borrow rules.
- Indexing uses `array[index]`. The index must be an integer. Negative indices and indices greater than or equal to the array length fail at runtime with a diagnostic and process status `1`; accesses are never unchecked.
- Assignment through an index follows the `mut` declaration rule: the array's root local must be mutable. Reads and writes evaluate the array expression and index exactly once, in that order.
- Current native support covers copyable scalar types, `str`, owning `String`, `Vec<T>`, and nested arrays. Indexed assignment targets a named mutable array local. Reads reject negative and out-of-range indices with a runtime diagnostic and exit status `1`. Structure and enum array elements remain unsupported.
- The compiler's internal calling convention and in-memory representation remain implementation details. This feature does not promise a C layout or a stable ABI.

## Namespace and resource-management design notes

- Namespace behavior is currently file-scoped: `namespace a::b;` qualifies following declarations and `namespace;` resets to root. Unqualified function, struct, and enum lookup uses the active namespace. Project modules reset namespace state at file boundaries. Block-scoped namespaces remain to be designed.
- RAII and destructors depend on ownership and move semantics. Define exactly-once destruction, cleanup order for nested resources, and cleanup on normal scope exit, `return`, `break`, `continue`, and runtime failure before implementation. Avoid adding a destructor hook before those rules are settled.

Later work may add symbolic constant lengths and array slices without changing the value semantics of `[T; N]`.

## Self-hosting path

Self-hosting is a staged acceptance goal, not a single feature. The existing Rust compiler remains the bootstrap compiler until the Ryn toolchain can build and run a Ryn implementation of itself. Prioritize the language and standard-library pieces in this order:

1. Dynamic `String` now has UTF-8-safe scalar indexing, slicing, direct scalar iteration over both borrowed `str` and owning `String`, append, concatenation, search, split, trim, numeric conversions, and an append-based builder API. Iterating an owning String consumes it; iterating a borrowed `str` keeps the borrow. Public `byte_at` is byte-indexed; `char_at` and `find` use Unicode scalar indices.
2. Heap allocation and `Vec<T>` now have growth, indexing, mutation, and consuming iteration. Add map/hash-map and set collections after hashing and equality contracts are defined.
3. Enums and `choose`, then fixed arrays, tuples, slices, and destructuring. Fixed arrays and simple type aliases are implemented. Keep the array value semantics above and extend the current Vec-slice call-borrow rules to array-backed slices before allowing more slice escape paths.
4. Generics and constraints, sufficient to express `Vec<T>`, `Option<T>`, `Result<T, E>`, and common collection APIs without monomorphization surprises.
5. `Option`, `Result`, error propagation, and typed runtime diagnostics. `exit(code)`, `panic`, and failed assertions now run generated cleanup for live compiler-known owners before process termination; nested custom drop glue and Ryn stack unwinding remain part of the ownership/RAII milestone.
6. Filesystem and path APIs, environment variables, process launch/status, stdin/stdout/stderr, and exit codes. These are required for a Ryn compiler to read source files and drive its build pipeline. A first owning `Path` wrapper is available in `stdlib/path`; expand it after references land.
7. File-scoped namespaces, qualified paths (`namespace` and `::`), multi-file module visibility, and local path dependencies are implemented. Add Git and registry fetching and preserve the documented cycle rules.
8. Complete the ownership model beyond its current scope: extend drop glue to maps/enums/nested aggregates, complete borrow/lifetime rules and settle cleanup for future heap/resource layouts. Keep garbage collection out of the design.
9. Scalar references and raw-pointer address/dereference forms now have an experimental implementation. Complete lifetimes and alias checking, then broaden the existing `sizeof`/`alignof` and C ABI/`repr(C)` subsets; extend typed function-pointer calls to aggregates and complete dynamic-library signature coverage as explicit system-boundary features. Add atomics/threads only after the memory model is settled.
10. Continue the Ryn-written compiler components in dependency order: connect the initial UTF-8 source manager and lexer prototypes, then add source IDs/structured I/O errors, recursive AST and arenas, parser, diagnostics/formatter, type checker, Ryn Guard, IR/code generation, then CLI and build orchestration. Use the existing Rust compiler to bootstrap each stage and keep a known-good compiler available for recovery.

The self-hosting acceptance gate is a Ryn-written compiler that can read multiple source files, report useful diagnostics, build a native executable, and successfully rebuild its own sources through `ryn check`, `ryn build`, and `ryn run`. Until then, keep each stage separately usable and tested; do not claim self-hosting based only on a lexer or parser written in Ryn.
